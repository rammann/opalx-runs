# asr61_dipole — the ASR61_300d map on its own

The first case in `g4bl/elements/` (then `g4bl_compare/`) to test a bend, and the first to use a G4beamline 3D
`grid` map. `asr61_300d_track.g4blmap` is 60 × 25 × 553 points on a 10 × 10 × 5 mm grid,
x = −200…390 mm, y = −120…120 mm, z = −1380…1380 mm, absolute Tesla, 56 MB. OPALX reads
it natively through `G4BL3DGrid`. `SCALE` on the `FIELDMAP` element is G4beamline's
deck-side `current=`, because neither reader normalises.

## Frame

`z` in the G4beamline input [mm] / 1000 == path length `s` in the OPALX input [m], until
the field starts to bend the orbit and `s` runs ahead of `z`. The centreline is straight —
no `cornerarc` — which is what makes the two frames one to one. In muE4 this magnet sits
between two `cornerarc` commands so the centreline follows the beam; here it does not.

The element's local frame is the map's own frame, so `Z` is the lab position of the map's
z = 0 — for this map its centre, not the field start. `Z = 1.500` puts the field at
z = 0.120…2.880 m, matching g4bl's `place M0 z=1500`. The orbit bends towards +x, which is
why the map box reaches to +390 mm on that side and only −200 mm on the other, and it
leaves the box sideways near x = 390 mm in both codes.

## How it is run

Both files are **generated by `../make_cases.py`** — do not edit them. Run the case from
the study root:

```bash
cd .. && ./run_all.sh asr61_dipole
```

## History

This case originally used an `SBEND` with `FMAPSCALE`, placed by `ELEMEDGE`. Neither
`FMAPSCALE` nor `SBEND` + `FMAPFN` exists on this branch, so it has been rebuilt as a
`FIELDMAP` placed by absolute position, which is also why every other element in the deck
is placed that way — OPALX allows one placement convention per beamline.

Its recorded result was on-axis field agreeing to 5e-8 T and exit |dx| ≤ 50 µm over a
41 degree bend. The rebuilt case reproduces that exactly (48.8 µm at the old step sizes),
and records all 19 particles where the old one dropped two. Running both codes at a step
size where they have converged brings the same number down to **8.4 µm** — see the study
README for the table, and for why almost all of the original 49 µm was step size rather
than anything to do with the map.

The superseded `compare.py` and `make_parts.py` were removed when the shared harness
replaced them. `make_parts.py` in particular had become a hazard: it wrote a 13-particle
`parts.txt`, while the generated deck declares 19.
